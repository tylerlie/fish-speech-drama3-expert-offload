共六种节点、三个独立工作流。本版为单音色与逐行拼接增加 **双参考重生**：始终保留原始音色参考，再加入上一轮生成音频。可选 0–4 轮，新版克隆工作流设为 4 轮。保留共用 API 参数节点、Reference 下拉媒体、本地上传与外接 AUDIO。

1.3.1：Reference 的“参考音频”改为下拉菜单，可复用 ComfyUI input 目录及子目录中的已有音频/媒体，省去重复上传；增加“刷新媒体列表”按钮。

```bash

cp -a /root/fish-speech-drama3-expert-offload/comfyui/fish_speech_local /root/ComfyUI/custom_nodes/
```

依赖与 1.0.0 相同。升级后重启 ComfyUI，再刷新浏览器。`Load Audio by URL` 由下方第三方插件提供，按需另行安装。

## 三个工作流

| JSON | 用途 |
|---|---|
| `01_单音色克隆或生成.json` | 参考全空普通生成，有参考双参考克隆；重生 4 轮 |
| `02_多角色长文本.json` | 一次提交整篇多角色文稿，保留以便后续验证官方修复；已接参数节点 |
| `03_拼接式多角色多语气.json` | 每行独立双参考重生 4 轮，输出最终完整拼接与分段数组 |

三个 JSON 已增加参数节点和可选 AUDIO 接口。原生多角色路径当前已知会在部分输入下漏读；本版没有修改或宣称修复该路径。旧 JSON 可以继续导入，前端会补出可选端口；不连接 parameters 时保留原有请求方式。

## 双参考重生：音色锚点与上一轮音频

在 **单音色克隆 / 生成** 或 **循环 Reference · 逐行克隆拼接** 上设置“重生轮次”：

| 轮次 | 每段请求数 | 行为 |
|---|---:|---|
| 0 | 1 | 只使用原始参考生成一次 |
| 1–4 | 2–5 | 首次生成后，追加指定次数的双参考重生 |

每次追加请求保留该音色的所有原始参考，并仅加入上一轮生成音频；不会累计之前所有轮次。只有一份原始录音时，追加请求恰好有两段参考；同音色原有多份样本时全部保留。原始录音和对应原文始终不改写。

生成样本的参考原文来自本段生成文稿，自动去掉方括号语气描述和尖括号标签，保留标签里的实际台词。生成文稿本身的语气标签始终保留。克隆时文稿不能只有标签、没有实际台词。

- **单音色无参考**：自动只做一次普通生成，无需断线或把轮次改回 0。使用 `reference_id` 的已保存音色若要重生，请改用 Reference 节点提供原始音频。
- **逐行多角色**：每行独立完成全部轮次，再处理下一行。所有参考在该请求内均为 speaker 0；只保留当前角色的原始样本和当前行上一轮音频，不把上一个角色或上一行结果传入下一行。
- **原生多角色**：保留原请求，不增加重生控件。需要双参考时使用工作流 03。
- **输出不变**：单音色输出指定轮次的最终 AUDIO；循环的“完整拼接”和“分段数组”只包含每行最终结果，中间轮次不混入数组，也不自动保存到磁盘。
- **参考交换无损**：原始与生成参考均使用单声道 24-bit FLAC；中间请求固定接收非流式 WAV，避免反复 MP3/Opus 中转。最后一次响应仍遵循 API 参数的音频格式和流式设置。
- **种子规则与本轮实验一致**：首次使用生成节点或参数节点给出的种子，重生第 1/2/3 轮分别加 1000/2000/3000，第 4 轮沿用第 3 轮种子。循环每行先按原有规则加 1；溢出回绕。选择“不指定种子”时所有轮次都不发送种子。
- **取消与失败**：每次请求前后检查取消；任一轮失败就停止，不暗中补抽或返回较早结果。取消不会保证已发送的 Fish 后端请求立刻停止。

新工作流 01、03 已选择重生 4 轮和 `single_chunk=true`，对齐本轮短段实验。单独新建节点或旧工作流省略轮次时默认 0，避免旧队列突然增加耗时。实际耗时随文稿、参考长度与请求数变化；03 的 N 行、4 轮会执行 5N 次推理。长文建议按情绪段落换行，每行仍需角色名；文本或音频上限不足时仍可能漏读或截断。

本功能没有额外下载 ASR 或评分模型，不会自动判断漏读、情绪优劣或音色漂移，也不是官网的 `quality-guard`。参考原文按目标台词生成，若模型实际漏读，插件不能自动校正该原文。已验证音频可解码和采样有效，不代表每一轮都有提升；试听后选择需要的轮次。

## API 参数：三个生成节点共用

添加 **Fish · API 参数（自部署）**，将 `parameters` 出口连接到生成节点同名输入。同一个出口可以同时连到三个生成节点，配置互不改写。正文和参考仍从原来的文本、Reference/References 输入。

本节点覆盖当前自部署 `/v1/tts` 的全部字段：正文 `text`、参考 `references` 由现有节点提供，其余13个请求字段由参数节点配置；`seed_mode` 只是插件的种子来源选择，不发送给 Fish。

- 默认 Temperature **1.0**、Top P **0.9**、每段生成上限 **1024**。种子默认沿用生成节点；循环逐段加1。也可统一使用参数节点种子，或不指定种子。
- `parameters` 是可选输入。不连接时不新增采样字段，由 Fish 使用服务默认值；原有生成节点的种子仍有效。
- `chunk_length`、`repetition_penalty`、`normalize`、`latency` 虽可传入，但当前 Drama 3 的实现限制已标在控件和提示中。它们不等于已实现托管服务的同名功能。
- `format` 支持 WAV/MP3/Opus/PCM，表示 HTTP 音频编码；插件解码后仍输出 AUDIO，最终保存格式在原生保存节点选择。建议使用默认 WAV，避免有损中转。
- `streaming=true` 仅支持 WAV。ComfyUI 会等完整响应接收后输出 AUDIO，不提供边生成边试听。
- `reference_id` 仅用于单音色且 Reference 全空，填写自部署服务已保存的音色ID。两种多角色方式依赖角色绑定，不允许一个全局 ID 覆盖所有角色。
- 请求日志会记录实际参数，不记录参考音频 Base64；可在 comfyui.log 核对。

完整字段、默认值和适用范围见 [API参数说明](docs/api-parameters.md)。Fish 服务、模型和启动脚本均无需修改。

## Reference：上传或连接外部音频

点击 Reference 顶部的“参考音频”即可展开已有媒体列表，包括 `input/fish_reference/` 中以前上传的文件和其他 input 子目录的媒体，无需再次上传。选择后可直接试听，参考原文仍需填写该文件实际说的话；换音频不会自动改写原文。

新增上传或手动拷入文件后，可点击“刷新媒体列表”更新下拉项，不需要重启服务。上传成功的文件会立即加入当前节点下拉列表并选中；其他 Reference 可刷新列表后复用它。保留“上传参考音频”“清空音频和原文”按钮。生成文稿仍由 ComfyUI 原生 Text (Multiline) 输入。

列表只扫描 ComfyUI input 目录及其子目录，不扫描客户端电脑或 output/temp；媒体没有音轨或无法解码时仍会报错。外部软链接不列入。刷新不会自动换掉当前选择、清空原文或删除外部连线；当前文件失效时保留原值并提示重新选择，防止误用另一份音色。

新增 `audio_in`（界面显示“外部音频（优先）”），可连接 [ComfyUI-LoadByUrl](https://github.com/romandev-codex/ComfyUI-LoadByUrl) 的 **Load Audio by URL → AUDIO**，也可连接原生 Load Audio 或其他标准 AUDIO 输出。其余两个输出 `SAMPLE_RATE` 和 `SAMPLES` 不需要连接。

```text
Load Audio by URL · AUDIO → Reference · audio_in → References → 生成节点
                                  ↑
                        在 Reference 填写对应原文
```

- **有连线**：只使用上游音频，本地文件即使存在或已失效也不读取。原文填写上游音频实际说的话。
- **无连线**：使用本节点上传的音频，保持原有行为。旧工作流导入后自动补出可选接口。
- **上游为空或无效**：明确报错，不回退到本地文件；希望使用上传文件时请断开 `audio_in`。
- 界面提示当前来源。连线时隐藏本地试听，防止误以为试听的是上游音频；可在上游另接原生试听节点。
- 上游需提供一段 AUDIO（`waveform` 为 `[1, 声道数, 采样数]` 的浮点张量及正整数 `sample_rate`），至少 0.1 秒；双声道转为单声道 24-bit FLAC。批次中有多段时请先拆分，避免不明确地只取其中一段。
- “清空音频和原文”只清空本节点的文件和原文，不删除上游连线；若还连着音频，需重新填写原文后才能运行。

下面的留空规则适用于**没有连接 `audio_in`** 时：

| 音频 | 参考原文 | 行为 |
|---|---|---|
| 空 | 空 | 空参考，汇总时忽略 |
| 有 | 有 | 有效参考 |
| 仅一项有内容 | | 明确报错 |

References 九路输入均为可选，可只填第九路，无需补齐或断开其他槽。单音色可以全部为空；两种多角色节点均至少需要一个有效克隆音色。

单音色的参考文本和生成正文不用角色格式。两种多角色方式的参考文本都写：

```text
小明：这是该录音实际说的话。
```

另一个槽：

```text
小红：这是另一段录音实际说的话。
```

中文冒号 `：` 和英文冒号 `:` 均可。录音原文必须与实际内容对应；参考原文不做情绪翻译。

最多九段有效参考，因此最多九个不同角色；同名的多个参考归为同一角色，但每段仍占一个槽。文件损坏或失效会报错，不当作空参考跳过。

## 新工作流：拼接式多角色多语气

导入 `03_拼接式多角色多语气.json`，在线已接好的 Reference 中填写音频与对应角色原文，其余留空。修改原生文本节点：

```text
小明：你准备好了吗？接下来要测试语音了。
小红：[开心]准备好了，我们出发吧。
小明：[低声]路上小心一点。
小红：[兴奋]好，马上出发！
```

**每个非空物理行是独立片段，每行都必须写角色名。** 空行跳过；文本框的视觉自动折行不算新行。同一角色可以连续出现，分别使用不同语气：

```text
小明：正常说话。
小明：[开心]这个消息太好了！
小明：[低声]我们小声一点。
```

语气可以省略。已转换的中文标签：`[开心]`、`[兴奋]`、`[生气]`、`[低声]`/`[耳语]`、`[大笑]`、`[悲伤]`，分别传为 `[happy]`、`[excited]`、`[angry]`、`[whisper]`、`[laughing]`、`[sad]`。英文标签和其他方括号内容按原样传递，实际效果取决于 Fish。

每行第一个冒号分隔角色和台词，之后的冒号都是正文：

```text
小明：时间：12:30，地点：河边书店。
小红：网址是 https://example.com。
```

这里不继承上一行角色：`时间：下午三点` 会被视为名叫“时间”的角色。应写成 `小明：时间：下午三点`。这与保留的原生多角色节点允许正文续行的规则不同。

### 两个出口

| 出口 | 类型与内容 | 工作流默认连接 |
|---|---|---|
| 完整拼接 | 一份 AUDIO，按文稿顺序拼接 | 原生试听 + 保存完整 FLAC |
| 分段数组 | ComfyUI 标准 AUDIO 列表，每个非空行一项 | 原生试听 + 逐段保存 FLAC |

数组不是批次张量，也不是九个固定出口；片段数取决于非空行数，不受九个角色槽限制。原生输出节点会对数组逐项执行，无需另外安装循环或列表插件。

完整音频默认保存到 `/root/ComfyUI/output/audio/DramaLoop/full_*.flac`，片段保存为同目录下 `segments_*.flac`，顺序由 ComfyUI 文件计数器记录。

### 节点参数与执行方式

- `gap_ms`：相邻片段之间额外插入的静音，默认 200 毫秒，可设 0–5000。只作用于完整拼接，数组里的片段保持原样；不在首尾额外补静音，也不裁掉模型本来的停顿。
- `seed`：首个非空行使用此种子，后续每段加 1，超过 32 位上限回到 0；空行不占种子。
- 每次请求只携带当前角色的参考及该行正文；该角色多段参考一并提交，全部映射为单人请求的 speaker 0。生成正文中不写多角色切换标记。
- 整篇格式及角色先校验，通过后才逐行串行请求。任一请求或音频解码失败，显示原文行号和角色并停止，不把部分片段当完整结果返回，不自动重试。重新运行从第一段开始。
- 支持段间取消；正在等待的 HTTP 请求不能保证立刻取消，也不能保证终止 Fish 后端推理。
- 保留 API 返回的音量、采样和自然首尾停顿，不自动做响度归一或裁剪。低声片段可能明显更轻。
- 同一批输出的采样率及声道数必须一致，否则明确报错，避免错误拼接。单行很长时仍由 Fish 内部分块；一行可写一个短句或自然段。

分段方式避免依赖一次多角色请求接续所有角色，但不等于模型绝不会漏字、发音错误或改变音色。本节点不加载 ASR 模型，不做自动台词覆盖评分；单人生成本身仍需试听。

## 原生多角色工作流的文本规则

`02_多角色长文本.json` 保留原规则：切换角色另起一行；不写角色的后续行接到上一个角色。正文行本身像 `时间：下午三点` 时，行首加空格表示正文。整篇仍一次提交 Fish，由 Fish 自行分块。单音色在重生轮次为 0 时保留单次生成方式。

## 封装接口

| 节点类型 | 输出 |
|---|---|
| `DramaReference` | `DRAMA_REFERENCE`，单条参考或 None |
| `DramaReferences` | `DRAMA_REFERENCES`，零到九条参考组成的列表 |
| `DramaAPIParameters` | `DRAMA_API_PARAMETERS`，供三个生成节点共用的请求配置 |
| `DramaSingleVoice` | `AUDIO` |
| `DramaMultiVoice` | `AUDIO`，原生多角色 |
| `DramaLoopReference` | `AUDIO` + `AUDIO` 列表；`OUTPUT_IS_LIST = (False, True)` |

循环节点必填输入为 `text`、`references`、`seed`、`gap_ms`，可选输入为 `parameters`、`regenerate_rounds`。参考仍连接原 References。文本输入端口接原生文本节点；示例 API prompt 可由 `tools/workflow_utils.py` 的 `to_prompt()` 转换。

Reference 的 API 输入是 `{"audio":"fish_reference/文件.wav","text":"角色名：录音原文"}`；空槽可用空字符串或省略两个可选字段。上传使用现有 ComfyUI 上传入口返回的相对文件名，不使用客户端绝对路径。清空只清空节点，不删除已上传文件。

连接外部音频时，API prompt 示例：`{"audio_in":["上游节点ID",0],"audio":"","text":"角色名：录音原文"}`。`audio_in` 是 ComfyUI AUDIO 连线，不能填写 URL 字符串。URL 填在 Load Audio by URL 节点里。
